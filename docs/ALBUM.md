# 控制台中的相册

相册是用户页面，默认直接读取本地索引、缩略图与原文件。只启动 nasctl 即可，
无需独立相册 HTTP 服务。索引沿用原 albumctl 的格式，以只读 SQLite 池读取；浏览
不会扫描、解码、修复索引或生成缩略图。已有远程相册配置仍然兼容。

## 本地配置与处理

`paths.index_file`（默认 state_dir 下的 index.sqlite3）、`paths.cache_dir` 和
`[[collections]]` 继续有效。空 API 地址默认本地模式；可显式设置：

```toml
[hub.album]
mode = "local"
```

在“管理相册”中从已配置的存储位置添加相对目录，可编辑名称、启用状态、同卷许可和私密设置。
私密目录的照片和视频留在原处，只有解锁保险箱后才能在相册和文件页中看到，见
[PHOTO-VAULT.md](PHOTO-VAULT.md#私密目录)。
最多 64 个托管目录、配置总量 64 KiB，以 0600 原子保存于 state_dir/album-directories.json，
不改写主配置。主配置中的集合继续由主配置管理。新配置立即作用于后续请求，不打断
正在读取的原图；移除配置隐藏相应列表／详情／缩略图，不删除原文件与索引行。
托管目录原文件通过已打开的 NAS 根目录读取，目录被替换成越界符号链接时仍拒绝访问。

### 处理整个目录

“相册管理 › 处理相册”选择一个目录后，可以“扫描并生成缩略图”、“只扫描”或“只生成缩略图”。
一个任务会处理完整个目录：nasctl 依次启动多批有界的处理程序（扫描每批 500 个文件、缩略图
每批 50 张），每批仍受隔离、内存阈值、运行模式和挂载检查约束，批与批之间停顿 2 秒。
任务中心显示第几批和已处理的数量。到达所选运行时间（最长 12 小时）、被暂停或资源保护
停下时，已处理的部分保留，再次开始会从剩下的文件继续。

### 缩略图怎么生成

- **JPEG：** 内置解码器（复制自 Go 标准库并加了“解码时缩小”）按缩略图需要的最小比例解码：
  1/8、1/4、1/2 或原尺寸。4800 万像素的照片只解出约 1000×750，内存从约 70 MB 降到 1 MB 以内，
  1/4 和 1/8 比原尺寸解码快约 3～4 倍。`decode.max_pixels` 和解码内存预算按**解码后的尺寸**
  计算，所以普通手机和相机照片不会再因为“太大”被跳过。渐进式 JPEG 要等最后一遍扫描才能
  出图，期间只保留缩小解码用得到的系数（1/8 时每 8×8 块 10 字节，原来是 256 字节），其余
  系数只记“是否为零”：1600 万像素的渐进式 JPEG 从约 100 MB 降到约 12 MB。
- **PNG：** 内置的流式解码器逐行解压、反滤波，每个像素叠到白底后直接累加进缩略图对应的
  格子，最后取平均（面积平均，比双线性缩放更不容易出锯齿）。内存只有缩略图本身和两行
  原图，与原图大小无关；隔行扫描（Adam7）的 PNG 也一样。5200 万像素的 PNG 从约 210 MB
  （隔行约 410 MB）降到约 14 MB。PNG 不再交给 libvips：同一张图 libvips 要 60 MB，隔行时
  200 MB。
- **以前没做成的大图：** 升级后第一次扫描时，之前因超出解码预算被跳过、或在处理程序内存
  上限处被停下的照片会自动重新排队，在后台照常一张张生成，不需要手动操作。
- **libvips（可选）：** 装了 `vips` 命令（Debian/Ubuntu：`apt install libvips-tools`，HEIC 还需要
  `libheif-plugin-libde265`）后，WebP、TIFF、HEIC、AVIF 交给它：它能流式处理大图，也能读
  Go 读不了的格式。它作为处理程序的子进程运行，受同一个内存上限约束。JPEG 默认仍用内置
  解码器（实测更快，省掉 libvips 每张的启动开销）；`formats.vips_for_jpeg = true` 可以改由
  libvips 处理。`formats.use_vips = false` 完全不用 libvips。RAW 格式仍不生成缩略图。
- **方向：** 缩略图按照片的 EXIF 方向转正（libvips 自动转正）。
- **并行：** 4 核及以上的设备默认同时运行 2 个处理程序（`decode.thumb_workers`，0 为自动，最多 4）。
  它们共用处理程序的内存上限：照片的预估内存加起来放得下才一起处理，大照片会等其他处理程序
  结束后单独处理。
- **扫描：** 读取照片信息时先读文件开头 64 KB，JPEG 的头部和 EXIF 不在其中时才读满 512 KB。

改了预算、装上或卸载 libvips 之后，下一次扫描会把之前因预算或格式被跳过的文件重新排队一次。
相册管理的“处理相册”里会显示当前用的缩略图引擎和并行数。

命令行 `nasctl album scan --limit N` 的 N 只计算新增、变化或推迟的文件，索引里没有变化的
文件不占名额，所以重复执行同样的命令会逐步覆盖整个目录（0.5 及更早版本中，没有变化的
文件也计入，重复执行总停在目录开头的同一批文件上）。还有剩余工作时，`scan` 和 `thumbs`
的输出以 `nasctl-batch: more` 结尾，退出码不变。

首次安装缺少索引时显示建立索引入口，读取不会创建空数据库。后台处理建立索引后，
下次读取自动连接。损坏索引显示不可用，后台不会擅自重建或覆盖。

处理任务由控制台按需以 `nasctl album ...` 重新启动自身执行，无需另装程序或手工
运行服务；`worker_binary` 仅供测试／打包时显式覆盖。扫描／缩略图每次必须指定 1–10000 项
和 1 秒至 2 小时上限；同一时间一个本地相册处理任务。缩略图继续使用原组件的逐文件
进程隔离／cgroup／内存与挂载检查，网页不提供跳过 cgroup 或强制解除资源冷却的入口。
可暂停后续处理、恢复许可，恢复不会自动开始扫描。当前任务可在任务中心停止。
取消先通知本次启动的处理进程组收尾，最多等待 15 秒后终止主进程；异常强杀或主服务
崩溃后的孤立进程只报告，不自动接管或杀死从旧 PID 记录猜测出的进程。

Linux 由 systemd 的 `Delegate=yes` 和可写的本服务 cgroup 子树提供隔离。NAS 先移到
自己的 supervisor 子组，让单次 `nasctl album` 处理进程在独立 task 子组等待私有启动门；
确认已进入该组后才准许加载配置和处理。处理进程再为解码器建立自己的受限子组。
这样满足 [cgroup v2 的内部进程约束](https://www.kernel.org/doc/html/latest/admin-guide/cgroup-v2.html#no-internal-process-constraint)，不会把 NAS 本身误当成解码器一起限额。
退出后只清理本次创建的已知空子组，不递归删除或杀死其他组；残留活跃进程时拒绝复用。
随附单元的总上限为暂定 256 MiB，包含 NAS、处理监督进程和解码器，默认解码器仍为
128 MiB，上层单次处理组增加 64 MiB 监督预算。总上限是硬界限，不能当成实际 RAM 用量；
部署后须测量并按自己的配置校正。浏览与扫描不因读取页面而建立解码处理组。

所有写入口要求操作者、可写控制台、明确确认、任务准入与审计。配置在执行任务时不可
修改；配置临时快照不含 NAS 用户、AI 或下载器凭据，任务结束删除。处理日志只保存
最后 4 KiB，进度来自该次处理 PID 的任务记录，不编造进度；没有进度记录时显示总量未知。
设置 mode="disabled" 停用相册。

## 从独立相册服务迁移

原 `albumctl serve` 独立网页和 `[hub.album]` 的 `api_base`／`token`／`public_url`
远程模式已移除。配置中仍有这些键时，nasctl 启动会提示删除；删除后相册直接读取
`paths.index_file`，索引、缩略图缓存和集合配置无需迁移。

## 已有功能

- 集合选择、文件名／目录搜索、类型、起止日期、排序；可显示缺失原文件、估计时间和 GPS 项。
- 每页 48 项，保留最近 100 页的返回位置；未应用的筛选修改不影响当前翻页。
- 缩略图画廊、文件详情、相机／尺寸／位置／EXIF 信息。缺失原文件仍可看已有缩略图。
- 照片默认只读缩略图，打开大图才读取原文件；原文件下载为独立附件。
- 常见视频容器交给浏览器播放；保留单段 Range／HEAD／缓存验证，不提供在线转码。
  容器可播放不代表其中编码一定受浏览器支持，失败时可下载使用本地播放器。
- 拍摄时间按相册记录的墙钟时间展示，不擅自转换不带时区的相机时间；估计时间有明确标识。

## HTTP 与资源边界

所有接口都在 `/api/v1/album` 下：

| GET 接口 | 内容 |
| --- | --- |
| `/status` | configured、connected、mode、index_ready、版本、暂停状态、安全错误摘要 |
| `/collections` | 已配置集合及索引数量 |
| `/media` | 筛选与游标分页；limit 默认 48、上限 100 |
| `/media/{id}` | 媒体详情 |
| `/media/{id}/thumb` | 已有缩略图／占位图；最多 2 MiB、10 秒 |
| `/media/{id}/raw` | 原文件，支持单段 Range 和 HEAD |
| `/media/{id}/download` | 原文件附件下载，支持 HEAD |

查询参数为 collection、q、kind、from、to、sort、cursor、limit、include_missing、
fallback、gps。响应中的媒体 URL 重写为同源地址，页面不使用相册接口返回的外部链接。
JSON 响应限制 2 MiB／10 秒；缩略图禁止 HTML 等非图片类型，SVG 占位图通过 sandbox
响应策略隔离直接导航。原文件要求明确大小，64 KiB 缓冲、30 分钟总时长和 30 秒读写
空闲上限；与其他媒体传输共享最多 3 个流槽，缩略图受全局并发上限约束。

本地管理接口为 GET `/settings`、POST `/directories`、DELETE `/directories/{code}`，
以及 POST `/tasks/{scan,thumbs,pause,resume}`。写入需要 X-Nasctl-Confirm:1；任务返回
job_id，进度与停止共用 `/api/v1/jobs`。元数据编辑尚未提供。

## 验证

Go 测试验证配置、不转发凭据、响应限额、重定向拒绝、身份验证、Range／HEAD／304／416
和缩略图内容隔离；新增本地读取、配置热更新、拒绝越界、后台凭据隔离与取消竞态验证。
`album-native.mjs` 验证真实 nasctl 的目录 UI 与按需启动 `nasctl album` 的暂停／恢复，
无需相册 HTTP 监听。`scripts/uitest/seed-album` 仅用于开发机／CI，要求命名的空目录或
带所有权标记的测试目录及 `--fixture-only`，生成 57 条合成索引和图片；
`album.mjs` 验证分页、过滤、详情、缺失项及原文件字节。视频记录仅验证 HTTP／DOM
流程，不能作为实际编码播放或真实 NAS 资源验证。

## 照片浏览与保险箱

相册左侧是“照片 / 相簿 / 保险箱”导航（手机上在标题下方），右侧是按月分组的照片网格。目录配置与处理在管理后台的“相册管理”（`#admin/album`）。顶部按钮按需展开搜索和筛选，“更多操作”中刷新，有权限时可进入相册管理；类型切换可只看照片或视频。相册铺满页面，只在内部滚动，手机上保留底部标签栏。

大图支持左右滑动或键盘方向键切换本页照片，轻点照片隐藏或显示浏览控件；照片信息按需展开，也可下载原图。保持每页 48 项的边界，打开一张照片才读取其原图，普通网格仅使用已有缩略图。

本地相册新增独立密码的[照片保险箱](PHOTO-VAULT.md)，加密原件、缩略图和元数据；请先阅读该文档的存储、备份和中断处理说明。
