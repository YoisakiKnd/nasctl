# 文件管理

文件管理以 CasaOS 的常用操作为功能参考，使用自己的 Go 后端与 Svelte 前端。当前
网页/API 支持浏览、搜索、预览、下载、上传、新建文件夹、复制、移动／改名、
跨存储移动、移入回收站、恢复和永久清理。支持多选批量复制／移动／回收／恢复，
以及经同一任务准入、确认与审计层执行的 CLI 写入。

## 文件页面

文件管理器参考用户提供的原生文件管理器布局：左侧位置栏、顶部位置标签和路径工具栏、
中间图标／列表视图、右侧可收起的预览详情、底部状态。单击选择，双击或 Enter 打开；
触屏上轻点直接打开文件或进入文件夹，长按弹出操作菜单，多选模式下轻点仍是选择。操作放在选中工具栏、右键／更多菜单与详情栏，
文件项不常驻一排按钮。右键菜单也可用 Shift+F10 打开，Escape 关闭并恢复项目焦点。
方向键切换选中项；位置标签可用左右方向键切换。

每个位置标签拥有独立的目录、查询和前进／后退历史，最多 8 个标签、每个方向最近
50 个位置。最近使用仅记录本次文件应用中打开的项目，最多 30 项。用户明确固定的
目录保存在当前浏览器 localStorage，最多 32 项，内容仅为根目录 ID、相对路径和显示
名称；启动时校验格式，未配置或不可用根目录的固定项置灰。视图偏好也保存在浏览器。
退出登录会清除标签及最近使用；不保存文件内容或凭据。

列表默认每页 50 项，搜索默认最多 200 个匹配项；本地配置可进一步降低这些上限。
搜索范围为当前目录及其子目录。首页搜索框提供明确的配置根目录文件搜索入口。文件图标使用内置矢量类型图标，不为网格请求全部原图或现场生成缩略图。
选中后延迟 150ms 请求详情，快速切换会取消旧请求；仅当前选中项有媒体预览，音视频
preload=none。新上传、移动等动作继续使用原有确认表单与后端权限检查。

页面小于 960px 时详情栏覆盖显示，小于 720px 时位置栏变成抽屉；布局按内容区宽度
响应，而不是只按整页视口。可写目录支持把文件拖到页面上直接上传（文件夹会被跳过并提示）；选中文件夹可“打包下载”为
ZIP（不压缩，超过复制上限时直接提示，不会生成半截的压缩包）；
网盘连接留到后续。

## 查看与编辑文本

`.txt`、`.md`、`.log`、`.json`、`.yaml`、`.toml`、`.ini`、`.conf`、`.csv`、字幕、脚本等文本文件
在详情栏显示开头的摘要，打开后显示全文。可写的存储目录里可以直接编辑：Ctrl+S 保存，
Tab 插入制表符，有未保存修改时关闭会先确认。工具栏的“新建文件”会创建一个空文本文件并
直接进入编辑。

- 最多显示和编辑 1 MiB。更大的文件只显示前 1 MiB，不能在网页里编辑；不是 UTF-8 的文件
  （二进制或 GBK 等其他编码）只提示下载。
- 保存时带上打开时内容的 SHA-256。文件在这期间被别人或别的程序改过，保存会被拒绝并
  说明原因，不会覆盖较新的内容。
- 新内容先完整写入并 fsync 到 `.nasctl-staging`，再原子替换原文件；保存失败时原文件不变。
  保留原文件权限；进程有权限时也保留属主，否则文件归 nasctl 服务用户。新建的文件遵循
  服务的 umask。符号链接和硬链接不能在这里编辑（替换会断开链接）。
- 文本永远按纯文本显示，HTML、SVG 等不会被当作页面渲染；原始预览接口也继续拒绝文本。
- 每次保存是一条 `files.edit` 任务与审计记录，和上传一样需要操作者确认与可写目录。

## 多选与批量整理

Ctrl／Command 单击切换所选项目，Shift 单击或方向键选择连续范围，空格切换当前项；
Ctrl／Command+A 或“选择本页”只选择当前页。“多选”模式让触屏可以连续点选。
换目录、标签、页码或排序会清空选择，避免对不可见项目执行操作。最多选择
`batch_max_items` 项，超限会提示而不悄悄截断。回收站提供复选框与批量恢复。

确认表单列出完整选择和目标文件夹。整批顺序处理，共享 `copy_max_entries` 与
`copy_max_bytes` 预算；复制目录的子条目也计入预算。同根改名、回收与恢复每次计一项，
不遍历目录内容。已完成的项目保留；同名冲突等单项失败继续下一项，预算、空间不足、
写入锁冲突、取消或超时会停止后续项目。结果区区分完成、失败和未开始，标明已发布目标
和源回收记录。取消不会撤销已经完成的项目。跨存储移动后的源内容可在回收站恢复。

父目录及其子项不能同时选择；重复项目、非法路径、只读写入或无效预算会在整批开始前
拒绝。每项实际执行时仍重新检查根目录、源文件、目标冲突与文件锁。批量任务不会永久
删除文件。逐项结果保存到任务事件中，离开文件页面后仍可从任务中心查看。

## 本地限额配置

`[hub.files]` 对上传、预览、目录读取／分页／搜索、回收站、复制和批量选择设上限。
完整默认值见示例配置；可降低但不能超过示例中的硬上限。零使用默认值，负数拒绝。
`default_page_size` 大于 `max_page_size` 时会收敛到后者。修改后重启，生效限额从
`GET /api/v1/files/roots` 的 `limits` 返回，页面按实际限额提交。复制和永久清理请求
也不能通过直接调用 API 提高本地限额。图片预览限额不限制 Range 音视频播放。

## CLI 写入

所有写入都需要明确的 `--confirm`，只允许本地操作者，`--agent` 不得使用。
复用与 Web 相同的可写根目录、运行模式、资源准入、文件锁和拒绝覆盖规则，任务与
审计写入同一个 hub.db。前台等待完成，SIGINT／SIGTERM 请求取消并收尾；输出包含
任务状态和操作结果，部分完成返回非零退出码。不要把非零退出码当成没有发生任何变更。

```sh
nasctl --config config.toml files mkdir --root documents --path 工作 --confirm
nasctl --config config.toml files upload --root documents --path 工作/a.txt --source ./a.txt --confirm
nasctl --config config.toml files rename --root documents --from 工作/a.txt --to 工作/b.txt --confirm
nasctl --config config.toml files copy --root documents --from 工作 --to-root archive --to 工作副本 --limit 1000 --max-bytes 104857600 --confirm
nasctl --config config.toml files move --root documents --from 工作 --to-root archive --to 工作 --confirm
nasctl --config config.toml files trash --root documents --path 工作/b.txt --confirm
nasctl --config config.toml files restore --root documents --id 回收记录ID --confirm
nasctl --config config.toml files purge --root documents --id 回收记录ID --confirm-name b.txt --limit 100 --confirm
nasctl --config config.toml --json files batch --batch-file ./batch.json --confirm
```

批量 JSON 最多 128 KiB，未知字段拒绝。例如：

```json
{"action":"copy","items":[{"root":"documents","path":"工作/a.txt"},{"root":"documents","path":"工作/b.txt"}],"to_root":"archive","directory":"工作","limit":1000,"max_bytes":104857600}
```

`trash` 使用 `root,path`，`restore` 使用 `root,id`，两者不填写目标目录；批量恢复使用
原位置，信息损坏或目标占用时可使用单项 `restore --to 新位置`。每个写入命令提供 `-h`。

## 启用

存储目录默认只读。仅为需要管理的目录设置 `writable = true`，然后重启：

```toml
[[hub.storage]]
id = "documents"
label = "我的文件"
path = "/mnt/data/documents"
writable = true
```

运行用户需要该目录的文件系统权限；systemd 部署还需为实际目录添加 ReadWritePaths。
目录不存在时不会自动创建成空存储。只配置存储目录也可运行 nasctl，无需相册集合或
追番服务。可写目录不能是 `/`，不能与 state/cache 或其他存储目录重叠；检查会解析
符号链接及尚未创建路径的现有父目录。

## 操作与上限

- 新建文件夹、移动／改名和恢复通过有界任务层执行，任务中心与审计保留结果。
- 写入需要操作者身份、可写根目录和页面中对本次目标的确认。客户端使用
  `X-Nasctl-Confirm: 1` 表示本次确认；确认绑定当前操作参数并记录审计，不授予持久
  权限。AI／helper 不能通过该标记获得写入权限，特权操作仍走原审批机制。
- 上传使用原始请求体和 64 KiB 缓冲，先写临时文件并同步，再原子发布。每个文件
  默认上限 8 GiB，本机配置可显式提高至 1 TiB，最多选择 100 个文件依次上传；每次上传最多 30 分钟，读流闲置 30 秒
  会中断。XHR 显示传输进度，发送到 100% 后仍等待服务器保存结果。
- 上传、改名、移动和恢复均拒绝覆盖已有同名目标。目标是文件夹或符号链接时同样
  拒绝；失败的上传不会截断原文件。上传停止／网络中断后应刷新列表确认结果。
- 一个存储目录同一时间执行一个写操作，跨 nasctl 实例通过文件锁协调。上传等文件
  传输另有全局互斥与流数量上限；运行模式、资源保护和只读设置仍会阻止任务。
- 同根目录内的目录移动与回收采用原子改名，不递归扫描目录内容。Linux／macOS 的
  内核和文件系统须支持拒绝覆盖的原子改名。跨文件系统或不支持此操作时会明确拒绝，
  不退回可能覆盖数据的改名；不同挂载点应配置为独立存储目录。
- 目录浏览和搜索有数量预算，隐藏文件及内部目录项也计入预算。搜索同时有深度、
  结果和时间预算；达到上限会报告截断，不把部分结果当作全部文件。

## 后台复制与移动

复制／跨存储移动返回 HTTP 202 和 `job_id`。页面显示已处理的字节数或条目数，结束
后自动刷新文件列表；任务中心保留结果与进度。总量尚未确定时不显示百分比。关闭
页面不会取消后台任务；可以在任务卡片或任务详情中明确停止。

每次复制默认 8 GiB，本机配置可提高至 1 TiB；仍最多 10,000 项、32 层目录、2 小时，
API 只能降低本地预算。时间上限独立于字节上限，慢速连接／存储须选择能在预算内完成的任务。使用
64 KiB 缓冲、一个文件接一个文件复制，目标上级目录必须已存在。复制先写目标存储
的 `.nasctl-copy` 私有暂存目录，完成并检查源文件身份、大小和修改时间后，以拒绝
覆盖的原子改名发布目标。源目录不需要 writable，目标需要。保留普通文件的修改
时间；新文件权限为 0640、文件夹为 0750，不保留所有者、ACL、扩展属性或硬链接关系。
符号链接保留链接文字、不跟随读取；设备、FIFO 和 socket 会拒绝。内部保留目录
跳过并在任务事件中报告，跨存储移动遇到这些目录会拒绝。

跨存储移动要求两边可写，先完整复制，再把源内容移入原存储的回收站，任务事件
记录回收 ID。源内容变化、回收站已满或停止发生在目标发布之后时，保留目标和源，
任务明确报告需核对。停止发生在发布之前时，源仍保留并清理未完成副本。源检查
不是文件系统快照；其他程序同时修改文件时应停止这些写入后重试。

后台任务仅能取消当前服务实例登记的原生任务，不接受 PID，也不停止外部进程。
手动发起的追番刷新／同步同样可停止，但已提交到下载器的任务由下载器继续管理。

## 回收与恢复

回收站位于每个存储目录的 `.nasctl-trash`。先写入并同步原位置、时间等恢复信息，
再移动内容；文件夹内容和原始文件保持原样。单根目录最多保留 1000 条回收记录，
不自动删除过期内容。恢复遇到同名目标时可以选择其他相对位置；缺少父目录时重建
父目录。如果恢复信息损坏但内容仍在，列表明确提示并允许手动指定恢复位置。

永久清理只接受回收 ID，不能直接删除普通路径。必须准确输入当前回收项名称并
确认本次操作。先检查整个回收项不超过 10,000 项、32 层目录，再开始删除；预算
不足时不会删除内容。删除后无法恢复，取消只能保留尚未删除的部分。中断记录会
显示“仅保留剩余内容”，允许继续清理或恢复剩余部分。符号链接只移除链接自身。

进程在移动前中断时，原文件仍在原位置；移动后中断时，可从回收站恢复。恢复后未
清理完的空记录会在后续回收时处理。这里只移除经过验证的空记录，不递归删除未知
目录或尚含内容的记录。断电与具体文件系统的持久化行为仍需目标设备验证。

`.nasctl-staging` 保存尚未发布的上传临时文件，`.nasctl-copy` 保存复制临时树，
`.nasctl-write.lock` 用于写入互斥。
内部目录带所有权标记；已有同名目录没有有效标记时拒绝使用，防止清理用户的其他
文件。进程异常退出遗留的已识别临时文件，在下一次上传取得锁后清理。内部名称
不会在普通文件列表中出现，也不能通过浏览／搜索／下载／写入 API 直接访问。

取消或关闭服务时，未完成传输会停止并清理临时文件；任务记录使用独立的短上下文
保存终态，避免客户端断开后任务一直显示运行中。已原子发布的文件不会因连接中断
被自动撤销；应通过文件列表和任务记录确认。

## HTTP API

| 路由 | 请求／用途 |
| --- | --- |
| `GET /api/v1/files/roots` | 每个根目录的 writable、已实现能力和上传大小上限 |
| `PUT /api/v1/files/upload?root=ID&path=相对路径` | 原始文件体，上传并拒绝覆盖 |
| `GET /api/v1/files/text?root=ID&path=相对路径` | 最多 1 MiB 文本：`content`、`revision`、`truncated`、`binary` 与 `editable` |
| `PUT /api/v1/files/text?root=ID&path=相对路径&revision=SHA256` | 原始 UTF-8 文本体；带 revision 时替换该版本，省略时只新建、拒绝覆盖；版本不符返回 409 `source_changed` |
| `POST /api/v1/files/mkdir` | `{"root":"ID","path":"文件夹"}` |
| `POST /api/v1/files/rename` | `{"root":"ID","from":"旧位置","to":"新位置"}` |
| `POST /api/v1/files/trash` | `{"root":"ID","path":"文件或目录"}` |
| `GET /api/v1/files/trash?root=ID&page=1&page_size=50` | 操作者分页读取回收内容 |
| `POST /api/v1/files/restore` | `{"root":"ID","id":"回收记录ID","to":"可选的新位置"}` |
| `POST /api/v1/files/copy` | `{"root":"源ID","to_root":"目标ID","from":"旧位置","to":"新位置","limit":10000,"max_bytes":8589934592}` |
| `POST /api/v1/files/move` | 与 copy 相同；同根使用改名，跨根复制后回收源内容 |
| `POST /api/v1/files/purge` | `{"root":"ID","id":"回收记录ID","confirm_name":"准确名称","limit":10000}` |
| `POST /api/v1/files/batch` | 上述批量 JSON；返回后台 job_id，逐项结果为任务事件 `kind=files.batch` |
| `POST /api/v1/jobs/{id}/cancel` | 当前实例活动任务；需 `X-Nasctl-Confirm: 1`，返回 202 |

写请求均需要确认标记和正常认证／同源检查。返回 `job_id` 与结果；冲突为 409，
只读或权限拒绝为 403，过大为 413，空间不足为 507。路径以配置的存储 ID 为边界，
不接受服务器绝对路径。

## 验证与剩余工作

Go 竞态测试覆盖拒绝覆盖、路径逃逸、只读／AI／跨站拒绝、临时上传清理、大小上限、
写互斥、回收上限、重开后恢复、恢复信息损坏、操作者逐次确认与取消任务终态。
实际编译的 Svelte 脚本通过真实 XHR 上传并验证改名、回收、恢复后字节一致以及同名
冲突保留原内容；实际浏览器另验证页面呈现、确认表单和新建目录。浏览器后续操作
工具出现派发超时，因此完整写入流程的证据来自 DOM＋真实 HTTP 测试。

后台复制／跨存储移动、预算／取消／冲突、源变化、清理预检／中断恢复都有 Go 测试；
Svelte DOM 测试通过真实 HTTP 验证复制、移动和准确确认后清理生成的临时测试文件；
实际浏览器另确认后台复制完成、处理量显示及文件列表自动刷新。
批量整理、可配置传输限额和 CLI 写入仍待继续。
Linux 文件系统运行与 NAS 的资源、权限、断电恢复尚未实测；交叉编译不替代这些验证。
