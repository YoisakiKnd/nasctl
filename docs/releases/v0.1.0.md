# nasctl v0.1.0

首个正式版本，提供 Linux amd64、arm64、ARMv7 三架构静态安装包。

- Svelte 多窗口桌面与 P2 文件管理器：标签、预览、搜索、多选批量、上传、复制移动、回收恢复及 CLI。
- 内置相册：目录配置、索引浏览与受限扫描／缩略图任务，日常无需独立相册 HTTP 服务。
- 自动追番：RSS 筛选、qBittorrent 控制和失败重试、路径映射、归档／NFO、字幕、播放续播及元数据维护；不包含 Telegram。
- 本地文件备份、SHA-256 校验、拒绝覆盖恢复，以及私有离线服务状态包与中断恢复。
- 真实存储容量、统一设置、任务记录、基础用户角色、首次管理员设置与本机恢复。

## 下载与校验

| 架构 | 安装包 |
| --- | --- |
| x86_64 | `nasctl-linux-amd64.tar.gz` |
| aarch64 | `nasctl-linux-arm64.tar.gz` |
| ARMv7 | `nasctl-linux-armv7.tar.gz` |

每包包含 `nasctl`、`albumctl`、配置样例、systemd 单元、部署文档和内部校验清单。
同时下载对应 `.sha256` 文件；以下以 arm64 为例：

```sh
sha256sum -c nasctl-linux-arm64.tar.gz.sha256
tar -xzf nasctl-linux-arm64.tar.gz
cd nasctl-linux-arm64
sha256sum -c SHA256SUMS
```

日常只启动 `nasctl`；匹配的 `albumctl` 放在同一安装目录，用于显式启动的受限处理任务。
新部署按包内 `docs/DEPLOYMENT.md` 完成初始化和账号设置。已有部署先建立并验证私有状态
检查点，再升级匹配的两个程序；不要直接覆盖实际配置或媒体目录。

## 验证范围

发布提交要求 main 上的完整 GitHub CI 已通过，包括 Go 测试／竞态、前端工作流、真实
Linux systemd/cgroup 相册处理及 ARMv7 模拟器冒烟。正式包另核对静态架构、版本标识、
所有文件 SHA-256 和上传后的下载字节。

实际 NAS 的资源／编码样本、磁盘满、挂载断开、断电恢复及真实 qBittorrent／TMDB 账号
仍需在目标环境验证；交叉编译和生成测试数据不能替代这些实测。定时追番、自动下载及
文件写入需按配置明确启用，网盘接入继续暂缓。
