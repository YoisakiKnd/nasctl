# nasctl v0.6.0

仿 Nextcloud 的新界面，修复进入管理后台后页面卡死；相册一次处理完整个目录，大照片和
HEIC 也能生成缩略图，生成更快；WebDAV 备份支持 123 云盘官方 WebDAV 这类下载跳转。从 0.5.x 升级只需替换程序；从更早版本升级请先
阅读[升级与迁移](../UPGRADE.md)。

## 新增与改进

- **新界面：** 蓝色背景上的透明顶栏放着各个应用，下方是圆角应用区；文件、相册和设置左侧
  是半透明的导航列表。管理后台和“我的”合并为“设置”应用，导航分“个人”和“管理”两组，
  设置内容按 Nextcloud 的样子排成平铺的分区。按钮、输入框、文件列表的尺寸都调大了一些。
  手机上应用在底部标签栏，设置导航收为抽屉。深色模式同步调整。
- **修复页面卡死：** 从头像菜单进入管理后台后，整页点不了任何东西。原因是菜单组件打开时
  给页面加的“禁止点击”没有被撤掉。现在菜单不再锁定页面，所有页面也共用同一个顶栏。
- **相册整目录处理：** “处理相册”不再要求填写“每次最多处理”。点“扫描并生成缩略图”后，
  一个任务会分批走完整个目录（扫描每批 500 个文件，缩略图每批 50 张），每批之间照常检查
  内存和运行模式；任务中心显示第几批、已处理多少。到达运行时间上限（最长 12 小时）或被
  暂停后，再次开始会从剩下的文件继续。此前没有变化的文件也计入“处理个数”，所以重复点
  总是停在目录开头的同一批文件上，这个问题已修复。
- **大照片也有缩略图：** 以前默认超过 1200 万像素的照片直接跳过，常见的 12MP 手机照片
  （4032×3024）都在其中。现在 JPEG 按缩略图需要的比例在解码时直接缩小（1/8、1/4、1/2），
  4800 万像素的照片只占不到 1 MB 内存，1/4、1/8 档比原尺寸解码快 3～4 倍。之前被跳过的
  照片在下次扫描时自动重新排队。缩略图也会按 EXIF 方向转正。
- **可选 libvips：** 装了 `libvips-tools` 后，PNG、WebP、TIFF、HEIC、AVIF 由 libvips 生成缩略图，
  iPhone 的 HEIC 照片终于有了缩略图（另需 `libheif-plugin-libde265`）。libvips 在同一个内存上限
  里运行；没装也不影响其他功能。
- **更快：** 4 核以上的设备同时运行 2 个缩略图处理程序（实测约快 1.85 倍），按内存预算排程；
  扫描读取照片信息时多数只读文件开头 64 KB，而不是 512 KB。
- **123 云盘等 WebDAV：** 回读校验、恢复和下载会跟随服务器给出的下载跳转（最多 5 次，
  目标须为 https），从网盘 CDN 读回的内容仍按 SHA-256 逐字节核对。WebDAV 账号密码只发给
  配置的服务器本身，不会发给跳转目标；上传、建目录等写操作仍然不跟随跳转。

## 兼容性

- 配置文件、数据库和状态目录格式都没有变化，可以直接替换程序，也可以直接换回 0.5.x。
- 页面地址不变；“我的”页面现在显示在设置应用中。
- `nasctl album scan --limit N` 只计算新增、变化或推迟的文件；还有剩余工作时，`scan` 和
  `thumbs` 的输出末尾多一行 `nasctl-batch: more`，退出码不变。
- 相册任务 API 的 `limit` 改为每批数量，`max_runtime` 上限提高到 12 小时。
- 新的可选配置项：`formats.use_vips`、`formats.vips_path`、`formats.vips_for_jpeg`、
  `decode.thumb_workers`，都有默认值。`decode.max_pixels` 现在按解码后的像素计算。

## 下载与校验

| 架构 | 安装包 |
| --- | --- |
| x86_64 | `nasctl-linux-amd64.tar.gz` |
| aarch64 | `nasctl-linux-arm64.tar.gz` |
| ARMv7（含常见玩客云 Linux） | `nasctl-linux-armv7.tar.gz` |

```sh
sha256sum -c nasctl-linux-armv7.tar.gz.sha256
tar -xzf nasctl-linux-armv7.tar.gz
cd nasctl-linux-armv7
sha256sum -c SHA256SUMS
```

升级步骤见包内 `docs/UPGRADE.md`。

## 验证范围

发布提交要求 main 上的完整 GitHub CI 已通过，包括 Go 测试／竞态、前端完整工作流（新增
菜单进入后台后页面仍可点击的检查）、真实 Linux systemd/cgroup 相册处理及 ARMv7 模拟器
冒烟。分批扫描另用真实处理程序验证过：一个任务分 4 批扫完 35 张新照片。缩略图用 24 张
1200 万～4800 万像素的照片验证：旧版跳过其中 18 张，新版全部生成；libvips 在 Ubuntu 24.04
容器里用真实的 libvips 8.15（含 HEIC）验证。WebDAV 跳转用
模拟的“网盘 + CDN”验证过；没有用真实的 123 云盘账号测试，真实 NAS 的资源和长期运行仍需在
目标环境验证。
