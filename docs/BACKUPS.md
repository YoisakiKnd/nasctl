# 本地备份

桌面“备份”现已支持选定文件／目录的本地副本：计划配置、手动执行、真实进度、版本历史、
SHA-256 校验、恢复到新位置、保留策略和不完整内容清理。无需额外备份 HTTP 服务。
**当前页面备份范围是所选普通文件；服务状态包及离线状态恢复仍在接入，不应将文件副本
当作已经覆盖配置、账号或正在运行的 SQLite 状态。** 实施进度见 COMPLETION-PLAN.md。

## 配置和执行

先配置原文件和备份位置两个独立的 `hub.storage` 根目录。原文件根可只读，备份根必须
显式 `writable=true`；两个根不能重叠。建议把备份位置放在另一块磁盘，同盘的副本不保护
磁盘故障。已有 `[backup]` 仍是外部备份繁忙检查，不会被本模块启动、停止或改写。

在页面新建计划，选择存储 ID、相对位置（`.` 表示整个根）、目标根、条目／字节／时间
预算和保留份数。最多 16 个计划，保留 1–32 份，单次最长 2 小时；条目和字节不能超过
当前 `[hub.files]` 的本地限额。确认执行时绑定完整已保存计划摘要；计划发生变化后，
旧摘要不能执行。配置保存在私有 `state_dir/backup-plans.json`，原子保存，移除计划不删副本。

默认复制字节上限仍为 8 GiB，本机可显式配置至 1 TiB；流缓冲仍为 64 KiB，内存不按
文件大小分配。时间预算仍最多 2 小时，应按存储速度选择可完成范围。已有大预算计划可
重新加载，当前本地策略调低后会拒绝超预算执行，不悄悄截断或删除历史副本。

保存计划时绑定配置位置、文件系统标识与目录身份。位置／挂载改变、重新启动后看到同路径
的另一空目录等情况会拒绝运行，避免空备份触发保留清理而删除最后一份有效副本。确认新
存储位置后编辑并重新保存计划。缺失挂载不会自动创建成空目录。

## 复制、校验和历史

- 固定 64 KiB 缓冲，顺序处理；包含隐藏文件。符号链接仅保存引用，不读取所指向内容，
  逃出根目录的链接也不会被跟随。系统保留的回收／暂存／备份目录不纳入文件副本。
- 原文件在复制期间检查身份、大小与修改时间；发生变化会失败。它是受校验的文件复制，
  不提供文件系统级瞬时快照；关键应用数据应使用后续状态包或先暂停应用写入。
- 私有 `.nasctl-backups` 存储完整版本和 `work-编号` 暂存。普通文件 API 不能直接列出、
  下载、复制或通过符号链接别名进入此目录；配置也不能把其子目录／别名注册为新根。
- 流式 `manifest.ndjson` 记录每个目录、文件或链接；普通文件记录字节数和 SHA-256。
  清单最多 8 MiB，单行最多 32 KiB，遍历预算和 32 层深度均有限。清单／内容核对通过，
  同步后才以拒绝覆盖的原子改名发布版本。失败或取消的暂存单列为“不完整备份”。
- 每个目标根最多 64 个完整或不完整版本，目录读取也有硬上限。只有新版本发布后才清理
  超出计划保留份数的旧版本。新版本永远保留；清理失败会明确报告新版本已保存和剩余清理。
- 进度区分复制、校验、恢复与清理阶段；任务结果持久化到任务中心，关闭窗口后可重开。
  关闭页面不取消后台任务；停止需要明确确认。已发布版本／目标保留，未完成部分可继续清理。

## 恢复与清理

先读取清单和全部文件，再复制到新位置的私有暂存区，重新核对暂存副本，最后才发布。
目标上级目录需要存在；已有目标始终拒绝覆盖。恢复字节／条目预算按该版本收敛，也不能
提高当前本地上限。校验失败、源变化或取消时不发布目标。零字节文件／空目录同样支持。

永久删除版本或清理不完整记录必须输入完整编号；确认绑定编号及版本清单摘要。
删除只作用于已标记的备份私有目录，原文件和已恢复目标保留。删除前预检有界目录树，
开始后取消会保留剩余内容，并以持久删除标记禁止把部分版本再次当作可恢复备份。
清理标记在版本目录之外，删除中断后仍可继续。未知／未标记的内容不会被自动清理。

## API

所有接口需要操作者身份。写入／重任务另需非只读控制台、运行模式／资源准入，以及
`X-Nasctl-Confirm: 1`；AI 凭据不能调用。重任务返回 HTTP 202 和 `job_id`。

| 接口 | 输入／结果 |
| --- | --- |
| `GET /api/v1/backup/settings` | 计划、摘要、运行状态 |
| `POST /api/v1/backup/plans` | `id,name,root,path,to_root,limit,max_bytes,keep,max_runtime`；位置绑定由服务端生成 |
| `DELETE /api/v1/backup/plans/ID` | 只移除计划，保留版本 |
| `GET /api/v1/backup/history?root=ID` | 完整版本、不完整记录、截断标识 |
| `POST /api/v1/backup/run` | `plan,plan_sha256` |
| `POST /api/v1/backup/verify` | `root,id` |
| `POST /api/v1/backup/restore` | `root,id,to_root,to,manifest_sha256` |
| `POST /api/v1/backup/delete` | `root,id,confirm_id,manifest_sha256` |
| `POST /api/v1/backup/cleanup` | `root,id,confirm_id` |

结果任务事件 `kind=backup.result` 区分版本／目标已发布、清理份数和告警；即使任务失败，
也必须查看 `published`，不能推断“没有发生任何变更”。

## 验证边界

相关 Go 竞态和实际 HTTP 验证包含字节恢复、损坏拒绝、拒绝覆盖、确认／身份／只读、
预算、取消、保留策略、位置变更保护、跨实例锁和未知暂存保护。编译 Svelte＋实际服务的
DOM 流程覆盖计划／执行／校验／恢复／冲突／精确确认清理，原文件和恢复副本保持一致。
这些不代替真实 NAS 的物理拔盘、断电、网络文件系统或硬件故障验证。

服务设置、任务和追番／相册数据库由独立的[离线状态备份与恢复](STATE-BACKUPS.md)保护。
