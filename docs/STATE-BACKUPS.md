# 服务状态备份与离线恢复

网页“备份”管理原文件副本。`nasctl state` 另提供服务状态包，供迁移准备、升级前检查点
和故障恢复。它需要在 NAS 本机由操作者运行，不能由 AI 凭据调用，也不会自动停止服务。

## 备份

先停止 nasctl Web、albumctl 扫描／处理组件及所有写状态的独立 CLI。旧版程序不参与新
锁协议，必须主动停止。备份期间也不要手工编辑配置、数据库或目录配置。

```sh
sudo systemctl stop nasctl-web.service
# 同时停止自己启动的 albumctl 任务及其他 nasctl 写入命令。
sudo install -d -m 700 /mnt/backup-private/nasctl-state
nasctl --config /etc/albumctl/config.toml state backup \
  --package /mnt/backup-private/nasctl-state/before-upgrade --confirm
nasctl --config /etc/albumctl/config.toml --json state verify \
  --package /mnt/backup-private/nasctl-state/before-upgrade
```

目标必须是新的绝对路径，父目录权限 0700，不能位于文件管理器已配置的存储根内。
包含配置，可能带服务令牌、下载器密码和订阅地址；请仅保存在自己的私有本地目录。
不要把此包分享给别人。程序不压缩、不加密、不上传，也不自动删除其他备份包。

包包含：当前 TOML 配置、hub 任务／模式／授权／审计库、存在的原生追番库和相册索引、
托管相册目录配置、本地文件备份计划、统一设置覆盖文件、本机账号与启用标记、已有追番元数据旧版本。不含原视频／照片、下载
目录、缩略图缓存、日志、临时处理配置或运行锁；原文件请使用网页文件备份另行保护。
不存在的可选模块数据库不会为了备份创建出来。

三个数据库目录及私有状态目录的独占锁同时保持到操作完成，参与该协议的任何服务／CLI
仍运行时立即拒绝。SQLite 使用分步在线备份 API 包含已经提交的 WAL，再将**暂存副本**
封成独立 DELETE-journal 数据库。它记录 `offline-exclusive` 一致性范围，不能把这个
离线协调方案说成运行中多个数据库的原子事务。

每个数据库最多 1 GiB，元数据旧版本最多 1000 文件／64 MiB，配置最多 1 MiB，目录和
备份计划各 64 KiB；清单最多 256 KiB，使用固定 64 KiB 流缓冲和 SHA-256。备份最多
20 分钟，CLI 总时限 30 分钟，Ctrl-C 会取消。取消或普通失败移除本次未完成包；断电后
缺少完整清单／哈希不匹配的目录不能通过校验，不会被当成有效包恢复。

## 恢复

再次停止全部写入进程。先 `state verify`，核对包和清单 SHA-256，再明确确认：

```sh
nasctl --config /etc/albumctl/config.toml state restore \
  --package /mnt/backup-private/nasctl-state/before-upgrade \
  --manifest-sha256 '<verify 输出的完整 SHA-256>' --confirm
```

恢复目标由**当前基础配置**确定。状态、hub 库、相册索引和配置文件位置必须与包的布局
摘要一致，只替换明确列出的服务状态文件，不写原文件存储根。统一设置覆盖文件属于
状态恢复范围，下次启动应用并继续经过原有配置边界校验。迁移到不同状态路径时，先
导出业务数据并准备配置，再建立对应布局的新包；本命令不会猜测路径映射。

恢复会：

1. 取得全部独占锁并重验包、文件内容、SQLite 结构、必需表及支持的版本。
2. 在 `state_dir/restore-checkpoints/<编号>` 保存恢复前一致状态包，最多保留 16 份。
   达到上限即拒绝，请先自行导出并审阅检查点；程序不会为了恢复删除旧检查点。
3. 在目标所在文件系统暂存，核对每个复制文件仍匹配已确认的清单，再在私有目录迁移兼容
   旧库。追番分配器合并当前记录／持久分配器／历史去重的编号高水位，防止复用外部下载
   器已经见过的订阅或剧集 ID。不向下载器发送请求。
4. 写入并同步恢复日志与阻止写入的标记，逐个替换已知状态文件。旧主库与 WAL／SHM／
   journal 保留到提交完成；旧侧文件不能附到恢复后的库。普通发布失败自动回滚。
5. 记录提交阶段并同步，核对发布结果、清理暂存及标记。重启后任务中心照常对旧的运行
   任务进行中断状态协调，不接管备份前进程。

**基础 TOML 配置不会自动激活。** 包内 `data/config` 保留原配置，恢复完成输出
`config_restored: false`。需要恢复配置时，先人工检查令牌、监听地址、存储路径和下载器
账号再安装它；避免同时悄悄启用旧监听令牌。统一设置覆盖文件中的下载器秘密和存储
目录属于恢复范围，重启前请一并审阅；相册缩略图可以按预算重建。

当前有追番／相册数据库或本机账号，而包没有对应内容时拒绝恢复；不能以缺失内容清掉
当前记录或账号登录。账号包必须同时含私有账号文件、启用标记及基础配置中的登录保护。
当前基础 TOML 也必须保留 `hub.setup=true` 或 `server.token`；包内的保护配置不被自动
激活，缺少当前保护时在建立检查点前拒绝恢复。账号恢复会带回备份时密码与角色，
重启前核对。普通忘记密码和损坏账号的固定范围本机
修复见 AUTH.md，不需要回滚其他模块。
不同文件系统上的多个文件不可能仅靠 rename 成为一个原子事务；本实现依靠独占锁、
持久日志、检查点和可重复恢复保证写入者不会读到未处理的中间状态。

## 中断后恢复

进程退出／机器重启后，只要恢复日志或标记还在，新版写入服务就拒绝启动并给出修复命令。
不要删除锁文件、日志或标记来绕过这个检查。仍停止所有写入进程，然后执行：

```sh
nasctl --config /etc/albumctl/config.toml state recover --confirm
```

未提交日志回滚到恢复前文件；已提交日志完成清理。日志严格限定目标、布局和完整摘要；
若文件被外部修改或日志损坏，则保留材料并拒绝猜测，使用检查点及日志排查。此命令不
自行杀进程、不覆盖未知冲突文件。目录 fsync 导致提交是否持久不明确时，同样交给此
入口读取日志上的实际阶段后决定，不能盲目回滚。

离线操作保存在独立私有 `state_dir/offline-state-audit.json`，最多最近 100 条／64 KiB，
含开始／结束、包编号／清单摘要、检查点编号和结果，不含配置或数据库行。该文件不从
旧包回滚。离线维护的 OS 操作者权限和明确确认用于恢复服务，区别于运行中任务的模式
调度；网页身份与运行模式仍约束各自的在线任务。

## 验证范围

本机 Go 竞态测试通过：运行写入者拒绝、三库与配置包、恢复后记录及追番高水位、原配置
不变、恢复前检查点、发布失败逐文件回滚、独立子进程退出后的写入阻止／恢复、已提交
日志清理、提交 WAL 捕获／旧侧文件隔离、摘要／别名／未列出文件拒绝、取消和审计上限。
独立 CLI 进程流程通过备份、校验、错误摘要拒绝、模式状态回滚和检查点复验。
CI 增加等价脚本，但没有据此声称远程 CI 已运行。真实 NAS 断电、物理挂载丢失、存储
硬件损坏和现场 systemd 升级／回滚仍需实际设备验收。

状态包还保存桌面应用入口和无密码的 WebDAV 版本历史。WebDAV 登录凭据、失败上传的密文暂存包不进入状态包；恢复后请重新填写连接。保险箱的完整备份可在 WebDAV 中选择“照片保险箱（加密数据）”，详见 [WebDAV 备份](WEBDAV-BACKUP.md)。
