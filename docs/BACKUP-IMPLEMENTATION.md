# 本地备份实施约定

对应 COMPLETION-PLAN 第 4 阶段。文件副本页面及其计划／执行／校验／恢复／清理流程已可用，
见 BACKUPS.md；服务状态包、多目录离线协调和离线状态恢复已接入 CLI，见 STATE-BACKUPS.md。
现有 `[backup]` 是 albumctl 让出资源的外部备份繁忙检查，保留其语义，不复用作新备份配置。

## 交付边界

- 本地备份计划使用已配置的存储 ID＋相对目录选择源和目标；保存在私有状态目录，
  校验路径、目录重叠、只读目标、名称、条目／字节／时间与保留数量上限。
- 顺序复制，采用独立私有暂存区，使用固定缓冲、数量／时间／深度预算；不跟随逃逸
  符号链接，不覆盖已有数据。完整检查后才发布备份；中断的暂存数据可识别、可清理。
- 每个备份有版本化清单与文件 SHA-256，明确来源、时间、配置版本、字节与条目数量。
  可选的状态备份含配置及 SQLite 状态；状态材料带凭据，只在本地私有目录保存，
  API 列表不回传这些内容。备份本身使用私有文件权限，不能通过文件管理器预览其内部。
- SQLite 必须使用在线备份 API 获取一致快照，不能直接复制正在写入的 db 文件或忽略 WAL。
  单库快照保持同一次提交，多库之间需协调暂停新增状态修改并明确记录一致性范围；
  不把逐库快照冒称一个跨数据库原子事务。
- Web 展示真实任务进度、历史、校验结果与失败原因，支持明确取消。计划修改、执行、
  恢复和清理都经过现有身份、确认、只读、运行模式、资源和审计层。
- 普通数据恢复先校验清单／每个文件，在新目标目录内发布，拒绝覆盖。确认界面明确
  选择版本、目标和规模；逐项结果可从任务历史重开。
- 恢复服务状态只在服务停止、持有状态目录独占锁时执行，保留恢复前检查点；先验证
  SQLite 结构与版本，再迁移兼容旧版。恢复追番状态时合并当前编号高水位，防止回滚
  后复用已经出现在外部下载器中的订阅／剧集 ID。恢复前后都要核对文件字节／数据库记录。
- 缺失挂载、源内容变化、磁盘不足、同名、损坏清单／哈希、取消／重启、错误权限与
  恢复过程中失败必须有真实测试；失败不删除源，不把不完整备份列为可恢复版本。

## 当前实现证据

`internal/dbsnapshot` 已实现私有、拒绝覆盖的一致在线 SQLite 快照：固定只读事务，
每步最多 32 页，单库字节预算上限 1 GiB，单次最长 5 分钟，取消与失败清理，quick_check、schema、页数、
SHA-256 和文件／目录同步。Go 竞态测试证明快照期间另一连接可提交 WAL 写入，而快照
仍保持原始提交；预算、取消、目标已存在及非私有目录拒绝测试通过。

`internal/anime.PreserveRestoreHighwater` 已提供私有暂存恢复库的编号合并准备：只读获取
当前持久编号、现存记录及已清理去重记录中的最大编号，再迁移并更新暂存库的分配器。
拒绝同文件／硬链接暂存、非私有目录和不支持的当前版本。该函数现由持有离线独占锁的
恢复流程调用，自己不负责停服务。测试验证恢复 schema 4 旧状态后
新订阅／剧集不复用当前／已清理编号，且当前库的分配器未改写。

`internal/statelease` 已接入 hub.db、追番库及相册写库的整个句柄生命周期：普通服务／CLI
持有共享文件锁，离线恢复须持有独占锁，忙碌立即拒绝；锁文件不删除，避免替换 inode
绕开仍在持有的锁。测试覆盖多个独立进程之间的共享／独占互斥、无效锁路径、三个写库
生命周期及持有独占锁时的编号准备。正式入口为 `nasctl state restore|recover`，通过独立子进程中断后的恢复测试。
旧版本进程不参与新锁协议，升级和恢复前必须停止旧版服务及独立处理组件。

文件副本部分已通过 Go 竞态、真实 HTTP、实际服务＋编译 Svelte DOM 的完整流程，
包括恢复字节、同名拒绝、损坏拒绝、确认和清理。文件系统及目录位置绑定拒绝挂载变化
和同路径空替代目录；私有路径别名与嵌套根保护有回归。服务状态包、离线独占协调和持久日志恢复流程
已实现并通过 Go 竞态／独立 CLI 验收；断电及实际 NAS 存储故障仍需设备环境验收。
